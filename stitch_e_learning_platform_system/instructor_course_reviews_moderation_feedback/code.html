Flawless curriculum. Minor clarification question on container memory swap cgroups.

The memory profiling on Node.js cluster workers was eye-opening. One observation: in the docker-compose.cluster.yml file, setting mem_limit: 512m without explicitly defining memswap_limit caused unthrottled swap trashing on Linux 6.8 kernels under high load. Did you intentionally rely on default kernel memory cgroup v2 controller balancing?

Lead Instructor Clarification 3 days ago

Spot-on observation Vikram! On cgroup v2 hosts, Linux defaults to allowing swap equal to memory size unless mem_swappiness: 0 or identical swap limits are set. We updated the repo template commit #9b4e1f to explicitly lock memory swap to avoid that kernel I/O trashing.
